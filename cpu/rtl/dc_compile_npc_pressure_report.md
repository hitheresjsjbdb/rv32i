# 第一部分：逻辑综合策略与时序优化说明

本阶段对应 `dc_compile_npc_pressure.tcl` 脚本，其作用是在 Design Compiler（DC）中完成 RV32 五级流水线处理器 `riscv` 的 RTL 读取、逻辑展开、时序约束和门级映射。与仅使用一个时钟周期约束并直接执行 `compile` 的基础综合流程相比，该脚本将时钟不确定度、预布局连线估计、复位时序例外以及若干已观测到的内部关键路径显式纳入优化目标。这样做的目的并非改变处理器的微体系结构，而是在 RTL 行为不变的前提下，使综合器能够将门级实现资源优先投入到更可能限制最高工作频率的组合逻辑锥中。

脚本首先将顶层模块设为 `riscv`，并定义工作目录和结果目录。RTL 输入采用兼容两种工程组织方式的策略：当脚本目录下存在单一的 `riscv.v` 文件时，将其作为包含顶层及所有子模块的扁平输入；若该文件不存在，则回退到读取 `./rtl/*.v` 的模块化输入。由于 `ALU_original.v` 与生产版本 `ALU.v` 同时声明 `ALU` 模块，脚本在模块化读取时将前者排除，从而避免重复模块定义。分析阶段传入 `SRAM` 和 `SYNTHESIS` 宏，使 SRAM 行为模型和面向综合的 RTL 分支在编译时保持一致。完成 `analyze`、`elaborate`、`link` 和 `check_design` 后，设计才进入约束与映射阶段；这一顺序保证了后续路径对象均建立在已展开的寄存器、宏单元和层级实例之上。

时钟约束以顶层端口 `clk` 为对象，时钟名称为 `clock`，周期为 5.0 ns，对应目标频率 200 MHz。时钟波形为 0 ns 上升沿、2.5 ns 下降沿，并显式设置 0.10 ns 的时钟 transition、0.15 ns 的 setup uncertainty 和 0.05 ns 的 hold uncertainty。因当前阶段尚未完成时钟树综合，脚本同时对 `clk` 使用 `set_ideal_network` 与 `set_dont_touch_network`。前者使 DC 不将尚不存在的时钟树延迟错误地计入数据路径，后者避免综合器为了数据时序而改写时钟网络。真实的时钟插入延迟、偏斜和 CTS buffer 选择应在后端 CTS/clock optimization 阶段重新分析和优化；因此，本脚本中的时钟模型属于带有抖动与建模裕量的 pre-CTS 理想时钟模型，而不是最终签核时钟模型。

复位端口若存在，则被固定为低电平，并从 `rst` 出发设置 false path。该处理符合复位不作为正常同步数据传输路径进行 setup/hold 检查的设计意图，可避免异步复位控制锥干扰正常流水线数据路径的排序。需要注意的是，脚本没有对普通顶层输入和输出设置 `set_input_delay`、`set_output_delay`、驱动能力或输出负载，因此当前时序目标主要反映片内寄存器到寄存器路径。若后续需要与片外总线、测试接口或其他 IP 进行时序闭合，应根据接口协议提供的外部时序预算补充这些 I/O 约束，而不应随意以内部路径约束替代接口约束。

在物理寄生尚不可用的综合阶段，脚本选择 `TSMC32K_Lowk_Conservative` wire-load model，并采用 top mode 估算层级顶层网络的连线负载。该选择使门级映射时的负载、扇出缓冲和单元尺寸决策不完全建立在零连线延迟的理想假设上。它仍然只是预布局估计；在 floorplan、placement 与 routing 完成并具备实际 RC 参数后，应以后端提取寄生的时序结果作为最终判断依据。

本设计已在 ALU 和 NPC 中将原有的算术加法结构替换为显式的 32 位 Kogge-Stone 风格前缀加法器。为避免 DC 将这些由 generate/propagate 网络构成的加法器重新识别并折叠为普通的算术表达式，当前脚本对 `U_NPC`、`U_NPC/U_JALR` 和 `U_ALU` 中匹配 `U_PREFIX_*` 的实例施加 `set_dont_touch` 与禁止 ungroup。这样，综合得到的网表保持 RTL 中给定的五级前缀传播结构，ALU 与 NPC 的时序比较也对应同一类加法器实现，而不会在不同综合轮次中被自动改写为不同的加法拓扑。

当前脚本还包含定点的内部路径加压。第一类为 NPC 分支目标路径：从 `U_ControlUnit/U_IDEX_Offset` 或 `U_IDEX_Offset20` 寄存器的 Q 端，到 `U_PC/PC_reg` 的 D 端建立 `NPC_OFFSET_TO_PC` path group，权重为 80、critical range 为 0.40 ns，并施加 4.55 ns 的 `set_max_delay`；若对象创建成功，还允许对 `U_NPC` 进行 boundary optimization。第二类为 IF/ID 中 rs1 字段到 IF/ID Offset 寄存器的控制路径，使用权重 100 和 4.5 ns 的最大延迟。第三类为指令 SRAM `U_IM/memory/Q[31:0]` 到 IF/ID Offset 寄存器 D 端的路径，后映射后使用权重 100 和 4.75 ns 的最大延迟。上述约束均通过寄存器 Q/D pin 获取端点，而不是直接使用模块端口，从而符合 DC 对内部 `set_max_delay` 端点的对象要求。

这些内部最大延迟约束的价值在于，它们能将已有的关键锥显式提升为优化优先级较高的目标，并避免优化后最差路径简单迁移到同一功能锥的其他输入类型。例如 NPC 后映射阶段同时收集 EX PC、Offset12、Offset20 和 JALR 基址寄存器输出，再统一指向 PC 寄存器 D 端，从而覆盖条件分支、跳转和 JALR 等不同的下一 PC 输入来源。脚本先进行一次 `compile -map_effort high`，再取得门级映射后才可见的端点；若后映射路径约束成功建立，则执行第二次高 effort compile，使该轮映射真正使用这些端点约束。这一“先映射、再定位、再优化”的过程尤其适用于综合前层级 pin 名称或部分寄存器 D pin 尚无法稳定查询的设计。

内部 Q-to-D `set_max_delay` 是针对指定组合逻辑锥的优化目标，而不是处理器功能接口本身的时序规格。它将 NPC、IF/ID 和 IM 这三类已定位的长逻辑锥分别赋予独立的 required time，使综合器能够在保持全局 5.0 ns 时钟约束的同时，额外压缩这些局部锥的门级延迟。由于这些约束的起止点均为真实寄存器 Q/D pin，优化对象清楚地限定在两个流水寄存器之间，不会改变寄存器边界和流水线拍数。

ALU 的 RTL 优化集中于加法和减法两条算术支路。`ALU_prefix_adder32` 先由 `p0=A^B` 和 `g0=A&B` 形成逐位传播/产生信号，再依次以 1、2、4、8、16 位为跨度构造五级 prefix network。每一级都把低位区间的 generate/propagate 信息合并到更高位，因此第 32 位的进位不需要经过 31 个串联全加器，而是在五级前缀合并后得到。加法支路以 `A`、`B` 和进位输入 0 作为操作数；减法支路以 `A`、按位取反的 `B` 和进位输入 1 实现二进制补码减法。对任意位 `i`，其输入进位由最终前缀级的 `g5[i-1] | (p5[i-1] & CI)` 形成，再与初始传播项异或得到和位。这使加法与减法共享相同的前缀网络结构和相同的逻辑深度。

两条前缀加法器的结果分别送入原有的 `ALUOp` 结果选择逻辑，逻辑运算、比较和移位分支仍保持原有实现。换言之，改动只替换了 `ADD_RESULT` 和 `SUB_RESULT` 的产生方式，不改变 ALU 的端口、控制编码、zero 标志定义或流水寄存器边界。这样，原本位于 `U_ALUOut` 数据路径上的加法/减法进位传播不再依赖逐位串行进位，而由固定五级的前缀传播网络完成；同时 ALU 的功能选择关系保持不变。

NPC 的 RTL 优化采用同一类 `NPC_prefix_adder32`，但其优化对象覆盖了下一 PC 生成中所有与加法有关的候选值。该模块同样以 1、2、4、8、16 位跨度构造五级 Kogge-Stone 风格前缀级，并被实例化到顺序 PC 加 4、EX 阶段 PC 加 8、Offset12/Offset20 分支目标计算、分支目标加 4 计算，以及 JALR 地址和 JALR 地址加 4 计算中。立即数与偏移量在进入加法器前已经完成符号扩展或左移构造：Offset12 和 Offset20 先补入最低位 0，再扩展为 32 位有符号操作数；JALR 基址则按照现有 RTL 的低两位对齐方式构造。前缀加法器仅替换算术实现，不改变 `NPCOp` 对下一 PC 来源的选择关系。

其中，`U_NPC_IMM12_PLUS4`、`U_NPC_OFFSET12_PLUS4` 和 `U_NPC_OFFSET20_PLUS4` 先产生立即数或偏移量的加 4 候选值；这些结果再作为 `U_NPC_OFFSET12_TAKEN_P4`、`U_NPC_OFFSET20_TAKEN_P4` 和 `U_JALR_ADD_P4` 的输入。因此，分支或跳转目标加 4 所需的两次算术运算均由前缀加法器实现，不会在同一条组合锥中留下普通 `+` 运算符推导出的逐位进位链。普通目标计算则由 `U_NPC_OFFSET12_TAKEN`、`U_NPC_OFFSET20_TAKEN` 和 `U_JALR_ADD` 完成，顺序路径由 `U_NPC_SEQ_PC_PLUS4` 产生，EX 阶段顺序候选值由 `U_NPC_EX_PC_PLUS8` 产生。所有候选值在 NPC 内部并行生成，再由原有组合选择逻辑输出 `NPC`、`PCA4` 和 `NPC_taken_p4`，从而保持模块端口和流水线控制接口不变。

因此，本设计的综合策略与 RTL 加法器优化是一一对应的：ALU 和 NPC 均以显式五级前缀网络替代加法/减法中的逐位进位传播；TCL 使用 `dont_touch` 和禁止 ungroup 保持该网络的映射边界；NPC 的分支、跳转和目标加 4 锥再通过定点 `group_path` 与 `set_max_delay` 获得更高的优化优先级。该组合使 RTL 中针对运算深度所作的结构化改动能够在综合阶段继续保持，并将优化资源集中到下一 PC 生成这一关键时序区域。
